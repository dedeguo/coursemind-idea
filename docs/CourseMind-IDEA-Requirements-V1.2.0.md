# CourseMind IDEA 插件需求文档

版本：V1.3.1（教室发布基线调整）
日期：2026-10-21
目标仓库：`dedeguo/coursemind-idea`
界面依据：[CourseMind-Plugin-UI.html](CourseMind-Plugin-UI.html)
功能参照：`coursemind-collect/extension` 中现有 CourseMind 扩展（运行于 Trae Code / VS Code / CodeBuddy 等宿主）

## 1. 本期目标与需求依据

本期先将 Trae Code 中 CourseMind 扩展的主要功能迁移到 IntelliJ IDEA，围绕“登录身份 → 配置 AI 工具 → 采集并上传 → 查看今日 AI 使用”形成可用闭环。本文中的“Trae Code 插件”指 CourseMind 扩展，不指重做 Trae 编辑器或 AI 对话能力。

长期仍面向 Java 程序设计、Java Web 开发技术、软件项目综合实训的统一教学环境，但课程、任务及提交体系需要与服务端重新共同设计，不作为本期目标或发布前置条件。

本版替代此前 V1.2.x 的首版范围、开发顺序和验收要求。需求不表示功能已实现；源码中存在接口也不表示当前部署服务已上线对应版本。后续界面开发必须遵循 UI 的页面结构、信息层级和交互，采用 IDEA 原生组件适配主题；示例身份、数字、会话正文及“演示成功”均不得作为真实数据或验收结果。

优先级：P0＝本期交付必需；后续＝另行设计后排期，不阻塞本期。

## 2. 范围与职责

| 范围 | 本期要求 |
| --- | --- |
| 身份 | 用户名/密码登录、身份与班级展示、修改密码、退出、共享登录态 |
| 今日 AI 使用 | 提问次数、会话数、平均轮次、多轮会话占比、主要主题、最近会话及可用的会话信息预览 |
| 连接设置 | 公网/校园内网切换、分别保存地址、展示生效地址、测试连接、上传凭证状态 |
| AI 工具配置 | Trae、Claude Code、CodeBuddy、WorkBuddy 的独立勾选、检测、批量配置和逐项结果 |
| 采集客户端 | 启停、路径、环境检测、部署/修复、状态及最近同步信息 |
| 工程交付 | Windows 首版、IDEA Ultimate 2025.1.3 优先适配与验收、插件 ZIP、说明与诊断 |

职责分工：IDEA 负责开发与调试；第三方 AI 工具负责对话；CourseMind 插件负责身份、配置与展示；共享 collector 负责采集、持久化队列与上传；服务端负责鉴权、去重和统计。插件不重复上传记录，不自行解析第三方聊天界面或 transcript，不重算服务端统计。

以下全部移到后续：课程列表与识别、任务说明和指导资源、教师提示、项目—课程/任务绑定、作业及文档提交、提交结果、工作台单点登录票据、项目体检、分级提示、答辩辅助、排行榜。现有 `/student/context` 仅是工作区上下文上报，不能视为课程任务绑定接口；本期不新增教学关联模型，也不因该接口存在扩展 UI 范围。

## 3. 用户流程与机房约束

管理员在机房维护模式中安装 IDEA、AI 工具、CourseMind 和 collector，通过普通设置页配置服务器与所需工具 Hook，使用测试账号验证真实采集，再退出并清除测试身份和队列后制作镜像。镜像不得包含有效账号凭据。

学生启动 IDEA 后在 CourseMind 工具窗口登录，在已配置的 AI 工具中正常提问，在 IDEA 中开发和调试，回到工具窗口查看个人信息、今日 AI 使用及采集状态。首次启动、重启和机房还原后均不弹欢迎页或分步向导；环境缺失时显示原因和设置入口。

还原卡的数据保留范围由机房策略决定，不承诺本地队列跨还原恢复。多项目、多窗口和多 IDE 共用同一 Windows 用户的采集环境，退出、账号切换和服务器切换均需协调共享身份及队列。

## 4. 工具窗口需求（P0）

### 4.1 未登录

- 展示 CourseMind、欢迎说明、用户名、密码、登录按钮以及“忘记密码请联系教师重置”。不提供注册、选课或任务入口。
- 展示当前网络、公网/校园内网标签、生效服务器地址和“修改连接设置”。用户名按现有协议映射为 `student_no`，不新增认证方式。
- 登录中防止重复提交；区分凭据错误、连接失败、超时和服务异常。成功读取真实身份后切换已登录视图，清除密码输入。
- 配置缺失时保留登录视图并提供设置入口，不自动启动向导。

### 4.2 身份与密码

| 编号 | 要求 |
| --- | --- |
| AUTH-01 | 展示服务端返回的姓名、学号/账号、班级、登录状态；缺失字段明确表示未知，不使用示例补齐 |
| AUTH-02 | 提供修改密码：当前密码、新密码、确认密码、取消、确认修改；检查必填和一致性，密码策略与服务端一致 |
| AUTH-03 | 修改密码使用现有接口；成功后更新返回的 access_token 并同步共享登录态，失败不提示成功；关闭表单清空密码 |
| AUTH-04 | 退出时清空当前身份、摘要、会话预览和密码输入；失效凭据停止使用，提示重新登录 |
| AUTH-05 | 复用共享凭据存储与跨 IDE 身份协议；启动、窗口恢复焦点和身份变化时重新校验，避免显示其他窗口的旧身份 |

### 4.3 今日 AI 使用

| 编号 | 要求 |
| --- | --- |
| STAT-01 | “今日 AI 使用”区域可折叠，显示统计日期，使用服务端返回的时间范围及时区 |
| STAT-02 | 展示 `prompt_count`、`session_count`、`avg_turns`、`multi_turn_ratio`；比例和小数格式遵循现有扩展与服务端口径 |
| STAT-03 | 展示主要主题的名称及次数，最近会话的时间、来源、轮次和标题；不限定只统计 CodeBuddy，不按当前 IDEA 项目擅自过滤 |
| STAT-04 | 登录后、窗口恢复焦点和手动刷新时按需更新；合并重复请求，阻止旧账号/旧服务器的在途响应回填新视图 |
| STAT-05 | 区分加载、今日无数据、失败、权限不足和登录过期；失败不显示为零，可保留同身份同服务器的旧数据并标记过期时间 |
| STAT-06 | 账号或服务器变化立即清空缓存及会话预览；数据仅来自本人授权接口，与工作台同源，不在插件重算评分相关指标 |

最近会话点击后在窗口内预览。当前已核对的统计响应仅有会话元信息（标题、主题、来源、时间、轮次等），不含对话正文。本期必须支持这些真实信息的预览；若复用现有授权接口能获取正文，再按实际契约展示。UI 中学生/AI 对话是示例，不承诺已有正文接口，不编造接口、不用示例正文填充；无正文时明确提示“暂不提供对话正文”。

来源优先使用服务端 `source`，未知值原样或以未知来源展示。现有扩展对旧服务端缺失来源回退为 `trae-code`，IDEA 若沿用该兼容策略必须注明兼容回退，不能将其作为真实工具检测或宿主归因证据。

窗口显示采集状态与最近同步时间，区分 Hook 已配置、收到事件、待上传、上传成功、暂停、未登录、异常和未知。无成功上传证据时不展示“采集正常”；最近同步不能使用统计请求成功时间代替上传确认时间。诊断细节放在设置或诊断入口，避免堆积在学生首页。

## 5. 设置页需求（P0）

设置位于 Settings / CourseMind，结构和交互参照 HTML，采用 IDEA 原生主题、字体、缩放和键盘交互。工具窗口右上角及登录区均可进入。

### 5.1 客户端配置

| 编号 | 要求 |
| --- | --- |
| CFG-01 | 插件内置公网和校园内网两套默认服务器地址，首次使用自动填入，默认选择公网；两套地址均可后续修改并分别持久化，校园地址为空时不得切换为有效配置 |
| CFG-02 | 校验 HTTP/HTTPS URL、规范化地址，展示当前实际生效的地址；默认地址在插件配置定义中集中维护，不在多个模块硬编码 |
| CFG-03 | 提供连接测试，显示正在检测、延迟或失败原因；连接成功只表示服务可达，不表示已登录或采集成功 |
| CFG-04 | 上传凭证仅显示可用、待登录、失效或未知，不显示密钥正文 |
| CFG-05 | 普通配置与凭据分离，展示共享配置来源和作用域；不静默覆盖其他 IDE 已配置的服务器 |
| CFG-06 | 应用保存并保留窗口，确定保存并关闭，取消丢弃未应用的表单修改；网络切换按身份/服务器切换规则执行 |

内置默认地址沿用现有 Trae Code 扩展的配置：

| 网络 | 插件内置默认地址 |
| --- | --- |
| 公网（默认选中） | `http://8.140.216.36:29236` |
| 校园内网 | `http://10.50.79.225:8000` |

已有用户或机房共享配置优先于内置默认值；仅在缺少配置时使用默认值。修改并应用后，重启插件继续使用已保存的地址和网络选择；插件升级不得用新的默认值覆盖用户已保存的配置。默认地址属于非敏感配置，不内置账号、密码或上传凭证。

优先 HTTPS；兼容现有部署使用 HTTP，界面如实标识连接方式。连接超时、地址和协议配置集中管理。

### 5.2 AI 编程工具

UI 中四项均纳入本期设置与配置范围，取消旧版“固定 CodeBuddy、Trae 只读、Claude Code 后续”的限制。它们是采集工具选项，学生无需在首次登录时选择。

| 工具 | source | 本期行为 |
| --- | --- | --- |
| Trae | `trae-code` | 复用现有扩展适配器检测和配置 |
| Claude Code | `claude-code` | 复用现有适配器及 Windows 执行环境要求 |
| CodeBuddy | `codebuddy` | 复用共享 settings.json Hook，覆盖 IDEA 内插件采集场景 |
| WorkBuddy | `workbuddy` | 复用现有扩展适配器检测和配置 |

- 初始勾选参照原型：Trae、CodeBuddy 勾选，其余未勾选；已有用户配置优先。勾选仅代表待配置对象，不能显示为已安装或已采集。
- 展示每项检测状态，按钮随勾选数更新“配置已勾选工具（N）”；未选工具不修改，不因取消勾选而删除既有 Hook。零选择时禁用操作或提示至少选择一项。
- 配置前生成变更预览，展示路径、事件、命令、作用域和共享影响；执行后逐项报告成功、跳过或失败，部分失败允许重试。
- 未安装工具、缺少执行环境或目标版本不支持时明确说明；提供四项配置入口不等于承诺采集任意版本或任何宿主。
- 工具适配逻辑和 Hook 合并规则以 `coursemind-collect` 现有实现为依据，实施时核对文件路径、事件、命令和版本，不在 IDEA 中另建采集解析器。

### 5.3 采集客户端

提供“启用 AI 对话采集”、采集程序路径、“检测采集环境”和“修复客户端”。显示实际 collector 路径、版本、可用性、采集开关和诊断结果；修复须报告具体处理项和剩余异常。

设置的应用/确定/取消只管理表单配置。测试连接和环境检测是即时只读操作；“配置已勾选工具”及“修复客户端”是即时执行操作，执行前说明修改范围，成功后不因设置页取消而自动撤销。Hook 的恢复通过专门的受管条目回滚实现。

## 6. 共享采集与安全约束（P0）

### 6.1 共享身份与隔离

Windows 复用 `%LOCALAPPDATA%\CourseMind` 的约定：DPAPI `CurrentUser` 加密的 `auth.dat` 保存学生凭据，`identity.json` 保存非敏感身份，`config.json` 的 `upload_key` 供 collector 使用 `X-Upload-Key` 上传。collector 不读取或刷新学生 JWT；PasswordSafe 可作镜像，不另建唯一凭据来源。

所有写入方必须协调共享配置与凭据的读写，采用一致的跨进程锁或现有等效协议，并校验服务器/身份一致性。不能仅在 IDEA 进程内加锁后宣称解决跨 IDE 并发问题。未登录时文件可能不存在，不据此认定共享机制损坏。

暂停、退出、切换账号或服务器时，停止以旧身份继续提交；队列必须保留原账号及服务器绑定，不能改投新身份或地址。无法恢复原凭据时可提供明确说明后的旧队列删除操作。现有 collector 在无 upload_key 时跳过事件、不建队列；未登录界面应说明未采集，不承诺登录后补录。

### 6.2 collector 部署与队列

- Windows 使用可直接运行的 collector.exe，不要求学生安装 Python；部署在当前用户可写的稳定目录，支持中文和空格路径。
- 复用共享 collector，检测版本、架构、完整性及协议兼容性；保留更新版本，禁止以插件自带旧版覆盖或降级。
- 部署和修复幂等，文件占用或权限失败给出原因；更新失败保留可用旧版，不清空队列。在线升级、macOS/Linux 另行排期。
- 沿用采集端的持久化、退避重试和服务端幂等去重；IDEA 不维护第二套上传队列。只有服务端确认接收才能算上传成功。
- `pending.json`/`failed.jsonl` 与诊断库用途不同；实施以当前采集端格式为准，不将诊断库当上传队列。

### 6.3 Hook 管理与内容完整性

修改前重新读文件、生成预览并备份，仅合并 CourseMind 受管条目，保留无关配置和第三方 Hook。重复配置不追加重复项；JSON 损坏或并发变化时停止写入并提示。回滚只处理受管变更，不整份覆盖用户后续修改；清理或卸载不删除其他 IDE 仍在使用的共享组件。

CodeBuddy 使用 `%USERPROFILE%\.codebuddy\settings.json` 的 `hooks.UserPromptSubmit` / `hooks.Stop`，命令调用共享 collector 并指定 `--source codebuddy`，不得携带长期凭据。该文件为用户级共享，影响 CodeBuddy IDE 等入口，不能宣称仅对 IDEA 生效。其他工具的配置文件、事件和命令形态逐项沿用现有适配器。

既有实测已确认 IDEA 内 CodeBuddy 能触发 Hook；本期仍需验证由 IDEA 插件独立写入配置、无需 Trae/VS Code 扩展在场也能采集。不能以“Hook 触发”或“配置文件存在”替代真实提问和回答上传成功。

CodeBuddy Stop 不保证携带完整回答；回答补全由 collector 处理 transcript 的落盘时序及文本提取，IDEA 不重复解析。实际来源/宿主/项目无法从状态可靠获取时显示未知或“存在近期采集”，不推断为“当前 IDEA 项目采集成功”。

### 6.4 凭据、隐私与诊断

密码、JWT、upload_key 不写入日志、Hook 命令、URL 或项目配置。仅采集适配工具允许的 AI 对话及必要上下文，不扫描无关文件；登录区和设置页保留采集说明及控制入口。

诊断默认排除凭据与对话正文，提供可定位的错误、组件版本和必要状态。所有网络、部署、文件检测均在后台执行，不阻塞 IDEA UI；长操作有进行中、结束与失败状态。

## 7. 本期接口与能力缺口

下表依据现有扩展 `extension/src/services/apiClient.ts`、统计类型与服务端 `server/app/api/student.py` 核对；联调时必须再次核对实际部署版本及响应，禁止新增同义接口或模拟成功。

| 接口 | 调用方/鉴权 | 本期用途 |
| --- | --- | --- |
| `GET /health` | 插件，无鉴权 | 测试服务可达性 |
| `POST /api/v1/student/login` | 插件，无鉴权 | `{student_no,password}`，获取 access_token、upload_key 和身份 |
| `GET /api/v1/student/me` | 插件，学生 JWT | 获取及校验本人身份与班级 |
| `POST /api/v1/student/change-password` | 插件，学生 JWT | `{old_password,new_password}`，成功更新返回的 access_token |
| `GET /api/v1/student/me/stats?range=today&recent_limit=5` | 插件，学生 JWT | 今日摘要、主题和最近会话元信息 |
| `POST /api/v1/records`、`POST /api/v1/records/batch` | collector，X-Upload-Key | 原有采集上传，不由插件重复调用 |

现有访问层使用 `{code,message,data}` 响应包络。统计数据含 `range{type,start,end,timezone}`、`summary{prompt_count,session_count,avg_turns,multi_turn_ratio}`、`topics[]`、`recent_sessions[]`。会话元信息含 session_id、machine_id、started_at、last_active_at、turn_count、topic_name、title、source，不含对话正文。

| 待核对项 | 处理原则 |
| --- | --- |
| 线上服务是否支持修改密码和统计的当前字段 | 以真实部署联调确认，失败显示明确状态，不用样例替代 |
| 最近会话正文是否已有本人授权读取接口 | 先核对既有扩展与服务端；本期保证元信息预览，正文按可用契约提供 |
| 四类工具的目标版本、Hook 开关和执行环境 | 分工具记录验证范围；无法检测的状态显示未知 |
| 共享凭据/队列/配置的并发协调 | 复用并核对现有协议；需修改共享组件时在采集端原仓库完成并记录版本 |
| 最近同步、内容完整性及宿主归因的可读状态 | 依据 collector 实际字段；不足时标记未知，不为 UI 捏造状态 |

课程任务、绑定、提交及工作台票据接口全部留到后续联合设计，不出现在本期接口交付清单中。

## 8. 兼容、构建与发布

主要开发、发布及教室验收目标为 Windows 上的 IDEA Ultimate 2025.1.3。release 默认使用 `platformType=IU`、`platformVersion=2025.1.3`、JDK 21 toolchain，最低平台声明为 `since-build=251`，不写 until-build；Java/Kotlin 输出仍为 Java 17 字节码，该字节码目标不代表兼容旧版 IDEA。日常开发与调试优先使用同一 2025.1.3 平台；本机 IDEA 2026.2.x / JDK 25 的 local 剖面仅作补充调试，其产物不作为教室版本兼容证据。不再将 IDEA 2023.3、2024.x 列为本期支持目标。

发布使用同一份 release ZIP，优先通过 Plugin Verifier 核对 IU 2025.1.3，再将 IU 2026.2 作为补充验证项，保存报告并说明不可获得或未验证的版本。教室 IU 2025.1.3 必须完成安装、亮/暗主题与缩放、设置、登录/退出/改密、双网络切换、collector 部署、Hook 配置及真实采集上传链路验收，并覆盖中文路径、普通学生权限和重启后的状态；IU 2026.2 补充执行安装及核心流程冒烟。未验证的 Community 或其他版本不得列为已支持。检查无阻断级兼容问题后交付 ZIP、安装/机房预配置说明、已知限制及验证记录；不自动发布 Marketplace。

## 10. 本期验收清单

| CUR-07 | 真实采集 | IDEA 插件独立配置 CodeBuddy，真实提问及完整回答上传且归属正确；其他三类工具在声明支持的环境逐项验证并记录版本 |

| CUR-09 | 今日 AI 使用 | 同账号同范围的四项指标、主题、最近会话与服务端/工作台一致；折叠、空状态、失败和刷新正确 |
| CUR-10 | 会话预览 | 使用真实会话元信息；无正文契约时明确提示，不展示 HTML 示例对话 |
