# CourseMind 面向 JetBrains 系列 IDE 的多课程覆盖扩展方案

版本：V1.0
日期：2026年10月19日；需求归档更新：2026年10月21日
文档性质：后续课程扩展需求与实施建议；须与服务端及工作台共同设计，不属于当前 IDEA 采集基础版范围，也不是已完成兼容的产品声明。

## 一、建设背景与目标

CourseMind 最初围绕 Java 程序设计、Java Web 开发技术、软件项目综合实训建设 IDEA 课程插件。当前教学中，学生使用 Trae Code 辅助编程，再切换到 IDEA 运行、调试，容易产生操作混淆和环境配置负担。教师的课堂观察是：学生更容易上手 IDEA 的运行、调试流程。

首要目标是将开发实践、AI 辅助和课程支持整合到日常开发环境中。进一步利用 JetBrains 系列 IDE 的共同平台，将课程范围扩展至 Python、C、C++、C# 和 Web 前端，形成统一的教学支持体系。

“统一”指共用课程身份、任务组织、采集协议、提交与反馈流程；不同语言仍使用适合自身的 IDE、编译器、解释器和项目结构。

## 二、产品定位与职责

> CourseMind 是面向 JetBrains 系列 IDE 的课程教学插件，与 CodeBuddy 配合，将课程任务、开发实践、AI 学习过程记录和成果提交整合到开发环境中，支持多种程序设计与软件项目实践课程。

| 组成 | 职责 |
|---|---|
| JetBrains IDE | 编写代码、项目管理、运行、调试与测试 |
| CodeBuddy AI 编程插件 | 解释代码、辅助实现、修改项目、排查问题 |
| CourseMind 课程插件 | 学生登录、课程任务、项目关联、Hook 配置、采集状态和成果提交入口 |
| collector 采集组件 | 接收 Hook 事件，按约定处理并上传 AI 对话数据 |
| CourseMind 服务端与工作台 | 课程与任务管理、记录存储、成果管理、教师查看与反馈 |

本扩展方案的第一阶段聚焦接通教学流程，不自行承担完整 AI 编程功能。项目体检、分级学习提示、代码答辩辅助属于后续增强。

## 三、课程与 IDE 覆盖规划

| 课程方向 | 目标 IDE | 主要教学活动 | 适配定位 |
|---|---|---|---|
| Java 程序设计 | IntelliJ IDEA | 基础语法、类与对象、运行与断点调试 | 首期主线 |
| Java Web 开发技术 | IntelliJ IDEA | Web 服务、接口、数据库、测试与调试 | 首期主线 |
| 软件项目综合实训 | 按技术栈选择 IDE | 需求、设计、实现、测试、迭代与验收 | 贯穿各阶段 |
| Python 程序设计 | PyCharm | 基础编程、脚本、数据处理、应用开发 | 优先扩展 |
| Web 前端开发 | WebStorm | HTML/CSS/JavaScript、Vue/React、接口联调 | 优先扩展 |
| C 语言程序设计 | CLion | 基础语法、数组、指针、结构体、调试 | 第二批扩展 |
| C++ 程序设计、数据结构 | CLion | 面向对象、容器、算法实现和测试 | 第二批扩展 |
| C# 程序设计、.NET 开发 | Rider | C#、.NET 应用、Web 项目 | 第二批扩展 |
| Unity 应用开发 | Rider | C# 脚本、交互逻辑、游戏与数字人项目 | 后续课程场景 |

IDE 产品能力不等于 CourseMind 已适配。CodeBuddy 官方安装文档列举了 IDEA、PyCharm、WebStorm 等产品；CLion、Rider 以及各产品的具体版本、Hook 行为，必须列入实测确认范围。

## 四、统一的学生学习流程

教师提前配置机房镜像：安装 IDE、所需语言工具链、CodeBuddy、CourseMind 和采集组件，完成 Hook 与服务端地址配置，退出测试账号并清除凭据。

学生课堂流程：

1. 登录 CourseMind，查看所属课程和当前任务。
2. 打开项目，将其关联到练习、实验或实训任务；已有有效关联时直接恢复。
3. 阅读任务与指导，使用 CodeBuddy 辅助实现。
4. 在当前 IDE 中运行、调试、测试，验证 AI 修改的结果。
5. 通过 CourseMind 入口提交或查看成果，在工作台获得反馈。

不提供首次使用向导，不要求学生重复安装采集组件、填写服务端地址或手动编辑 Hook。保留设置页，供教师维护及学生查看状态、按需修复。

“学生只需登录”适用于已预配置的 CourseMind 教学环境；CodeBuddy 的独立账号、授权和会话是否可用，需在机房部署时另行验证，不能由 CourseMind 登录自动保证。

## 五、课程扩展阶段的共用功能

| 功能 | 要求 |
|---|---|
| 登录与身份 | 服务端确定学生身份；切换账号后不沿用上一位学生的数据归属 |
| 课程与任务 | 同一学生可有多门课程；根据当前项目明确当前课程、任务 |
| 课程面板 | 展示任务说明、实验指导、资源和提交入口 |
| 项目关联 | 支持项目与课程任务建立、查看、变更关联；提交和上传均携带明确上下文 |
| Hook 设置页 | 展示状态，支持检查、应用、修复、移除；修改时保留非 CourseMind 配置 |
| 采集与状态 | 展示采集组件、Hook、登录和最近上传结果；失败信息可操作、可理解 |
| 工作台跳转 | 待服务端签发及兑换票据能力交付后，进入对应课程或任务，避免在 URL 暴露长期凭据 |
| 成果提交 | 提供任务对应的代码或文档提交入口及结果；可优先复用工作台能力 |

AI 对话采集链路：CodeBuddy → Hook → collector → CourseMind 服务端。

采集能力以实测为准，分别确认事件触发、用户输入、AI 回复、会话标识、记录路径及完整性。不能因为 CodeBuddy 可以安装，就认定所有对话模式都能采集。

## 六、技术架构与兼容边界

### 6.1 一个代码库，通用核心与语言增强分离

通用核心使用 IntelliJ Platform 公共能力，实现工具窗口、设置、项目关联、HTTP 通信、文件与进程管理。平台依赖应正确声明；核心不强制依赖 Java 专用插件。

语言增强独立注册、按可用能力加载。JetBrains 支持可选插件依赖，但不能仅修改依赖声明：通用类也不能直接引用缺失的语言 API，否则仍可能加载失败。

| 层次 | 内容 | 实施原则 |
|---|---|---|
| 平台通用层 | 身份、界面、任务、设置、采集、跳转 | 所有目标 IDE 复用 |
| IDE 适配层 | 产品识别、能力检测、必要的路径或运行差异 | 按实际差异增加，避免按 IDE 复制整个项目 |
| 语言增强层 | Java/Python/C/C++/C# 专用分析 | 后续按课程需求开发，可选启用 |
| 服务端 | 课程任务、对话与提交管理 | 保持统一协议，支持不同语言与 IDE 元数据 |

目标是在兼容条件允许时使用同一插件包覆盖多个 IDE。是否最终需要拆分发布包，依据版本范围、依赖和验证结果决定，不预先承诺所有版本通用。

### 6.2 Rider 的特殊处理

Rider 采用 IntelliJ Platform 与 ReSharper 后端结合的架构。登录、面板、Hook 管理等平台功能可作为优先验证对象；以后若要深入 C# 代码语义、检查和重构，需要评估 Rider 专用扩展机制，不能直接套用 Java PSI 实现。

### 6.3 工具链仍由课程环境预配置

| 课程 | 需要预配置的环境示例 |
|---|---|
| Java | 课程指定 JDK、构建工具及必要运行环境 |
| Python | 解释器、虚拟环境策略与课程依赖 |
| 前端 | Node.js、包管理器及项目依赖策略 |
| C/C++ | 编译器、调试器、构建工具和课程项目模板 |
| C# | .NET SDK；Unity 课程另需 Unity 编辑器及相应配置 |

CourseMind 可显示环境状态或指导入口，但首版不承担通用工具链安装器职责。

## 七、课程数据与多 IDE 协作

建议在既有协议上评估补充 IDE 产品及版本、插件版本、操作系统、课程、任务、项目关联、语言和采集来源等元数据。字段以服务端实际模型为准，正式开发时再确定迁移方案。

同一学生同时打开多个 IDE 或项目时，不能只依赖一个全局“当前课程”。Hook 事件应优先通过事件提供的工作目录、项目映射等可靠信息确定归属；无法确定时提示关联或暂存待确认，避免静默归到错误课程。

采集来源与 IDE 产品分开记录，例如来源为 CodeBuddy，而宿主 IDE 为 PyCharm。重试与重复 Hook 触发应具备去重机制。账号退出、切换或机房还原后，待上传数据必须保持原身份归属，不能上传到新账号名下。

教学分析以学习支持为目的。采集范围应向学生清楚展示，不自动扩大为上传整个项目或无关文件；编辑次数、调试次数和 AI 使用量不能直接作为是否理解代码的结论。

## 八、课程扩展的分阶段实施安排（基础版之后）

| 阶段 | 主要工作 | 完成依据 |
|---|---|---|
| 第一阶段：稳定 Java 主线 | IDEA 中打通登录、任务、项目关联、CodeBuddy Hook、上传与提交 | 完整课堂流程稳定，机房还原后可复现 |
| 第二阶段：验证通用核心 | 梳理 Java 强依赖；接入 PyCharm、WebStorm 验证 | 两类 IDE 完成相同流程，修复共享功能差异 |
| 第三阶段：扩展 C/C++、C# | 验证 CLion、Rider，确认 CodeBuddy 与 Hook 支持；补充工具链部署规范 | 各目标环境获得独立验收记录 |
| 第四阶段：教学增强 | 按实际痛点开发课程体检、分级提示、答辩辅助等 | 有规则依据、学生反馈与教师使用证据 |

建议先保持课程功能和采集协议一致，再扩展语言分析深度。无需等待全部 IDE 适配完成才开展 Java 课程试用。

## 九、验证与验收要求

建立“IDE 产品 × 版本 × 操作系统 × CodeBuddy 版本”的支持矩阵。初期优先验证实际机房 Windows / IDEA Ultimate 2025.1.3 环境；当前 IDEA release 使用 IU 2025.1.3 / JDK 21 / since-build 251，Java/Kotlin 输出仍为 Java 17 字节码。IU 2026.2 作为补充验证，其他产品与版本按需求扩展，不沿用历史 2023.3 最低版本承诺。使用 Plugin Verifier 检查目标 IDE 的二进制兼容性，再执行实际交互验收；两者不能互相替代。

每个准备宣布支持的目标环境至少完成：

1. 安装、启动、打开项目，CourseMind 可正常加载。
2. 登录后正确显示身份、课程与任务。
3. 项目关联、任务查看、工作台跳转和提交入口可用。
4. CodeBuddy 发起真实对话，验证 Hook 事件及输入、回复采集范围。
5. 服务端记录的学生、课程、任务、项目归属正确。
6. 网络中断、恢复与重复触发不导致错归属或重复记录。
7. 多项目、多 IDE 同时打开时，数据归属正确。
8. 退出、换号、重启、机房还原后，不沿用上一位学生凭据。
9. Hook 修复或移除不破坏其他已有配置。
10. 不安装 Java 语言插件的目标 IDE 中，通用核心仍可正常使用。

验收结论分为“已验证支持”“待验证”“暂不支持”，不将设计目标写成既成能力。

## 十、与现有需求文档及命名的关系

本方案承接[CourseMind IDEA 插件需求文档](Requirements-V1.2.0.md) V1.3.0 移出的教学需求。当前基础版先完成 Trae Code 中 CourseMind 扩展主要功能及 HTML UI，包括身份、四类工具配置、采集管理和今日 AI 使用；本文的课程、任务、绑定、提交和免登录均在之后单独设计及排期。机房预配置、设置页管理 Hook 和无首次向导约束继续适用；本文以 CodeBuddy 描述课堂场景，不限制基础版其他工具支持范围。

后续可将对外定位调整为“CourseMind JetBrains 课程插件”。当前 coursemind-idea 仓库名、插件 ID 和发布身份可保持，是否更名另行评估，避免为扩大定位引入无必要的迁移。

新增课程不意味着只改插件名称：服务端课程任务、提交规则、教材资源和验收标准也需要对应配置。跨 IDE 能力解决统一入口与过程记录，课程教学设计仍由教师按语言和目标组织。

## 十二、课程与任务扩展需求（由 IDEA 本期需求移入）

整理日期：2026年10月21日。本文以下能力属于后续规划，需插件、服务端与工作台共同设计后单独排期，不属于当前 IDEA V1.3.0 采集基础版的开发或发布门槛。接口缺失不通过客户端静态示例、空壳面板或首页跳转替代。

### 12.1 教学目标与角色

在稳定的登录、Hook 配置、真实采集和今日 AI 使用基础上，形成“查看课程任务 → 关联当前项目 → 使用 AI 辅助 → IDE 运行与验证 → 提交成果 → 查看确认结果”的学习流程。优先验证 Java 程序设计、Java Web 开发技术、软件项目综合实训三类课程，再扩展其他 JetBrains IDE 和课程。

| 角色 | 职责与权限 |
| --- | --- |
| 学生 | 仅访问本人可用课程、任务、项目关联及提交记录 |
| 教师 | 通过服务端发布任务、指导和资源，查看成果并反馈；插件不建设教师编辑系统 |
| 管理员 | 维护课程/班级及权限、机房环境和服务端配置 |
| 插件 | 展示授权数据、管理当前项目关联、提供对应工作台入口和结果刷新 |
| 服务端与工作台 | 统一鉴权、教学模型、关联关系、提交生命周期和票据兑换 |

### 12.2 课程识别与任务面板

| 编号 | 需求 | 验收要点 |
| --- | --- | --- |
| EXP-EDU-01 | 登录后读取本人可访问的课程；多门课程可切换，不以姓名、目录名或本地可编辑字段确定权限 | 无课程、权限不足、加载失败和课程失效有明确状态 |
| EXP-EDU-02 | 展示课程下的练习、实验或实训任务及其状态 | 切换课程清除旧任务；仅显示真实授权数据 |
| EXP-EDU-03 | 任务详情提供说明、实验指导、教师学习提示及资源链接 | 展示内容来自服务端；资源不可用有反馈，不内置示例作为正式内容 |
| EXP-EDU-04 | 提供当前课程/任务上下文和任务切换入口 | 不新增首次使用向导；不得将其他项目窗口的任务静默替换为当前任务 |

任务发布范围、开放/截止时间、可见性、资源格式、排序与分页等由联合设计确定，未确认前不冻结客户端字段和业务规则。

### 12.3 当前项目与任务关联

| 编号 | 需求 | 验收要点 |
| --- | --- | --- |
| EXP-BIND-01 | 当前 IDE 项目可建立、查看、更换和解除课程/任务关联 | 关联须由服务端校验身份及任务权限；不能以目录名称猜测任务 |
| EXP-BIND-02 | 允许恢复仍有效的已有关系，明确展示关联对象及状态 | 关联失效或权限变化提示重新确认，不沿用无权限关系 |
| EXP-BIND-03 | 多窗口、多项目、多 IDE 保持各自上下文 | 不仅使用一个全局“当前课程”；事件无法可靠归因时显示未关联/待确认 |
| EXP-BIND-04 | 账号或服务器变化后立即清除旧关联视图并重新校验 | 旧队列保持原身份和服务器，不能重写为新任务归属 |

共同确定稳定项目标识、目录移动/Git 仓库克隆的处理、单项目与多个任务的关系、关联存储作用域、并发冲突和解除历史。现有 `/api/v1/student/context` 仅为上下文上报，不能代替项目—课程/任务关联契约；既有记录能否补关联、何时绑定和如何审计均需另行设计。

### 12.4 成果提交及结果

| 编号 | 需求 | 验收要点 |
| --- | --- | --- |
| EXP-SUB-01 | 从当前课程、任务及项目进入对应成果提交页面 | 打开正确目标，不以工作台首页跳转替代任务入口 |
| EXP-SUB-02 | 支持课程要求的代码或文档材料，优先复用工作台上传与详情能力 | 文件类型、体积、版本、补交和重复提交规则由服务端统一校验 |
| EXP-SUB-03 | 显示服务端确认的提交状态、时间及可用反馈，并支持刷新 | 浏览器已打开、上传已发起不等于提交成功；失败可重试且不产生重复成果 |
| EXP-SUB-04 | 关联或权限变化时重新确认提交目标 | 不将成果提交到其他账号、任务或服务器 |

提交模型、状态流转、幂等键、代码仓库链接与文件上传边界、教师批阅/反馈、截止后策略需共同设计。插件不在未定义协议前实现独立提交系统。

### 12.5 工作台免登录与定向跳转

| 编号 | 需求 | 验收要点 |
| --- | --- | --- |
| EXP-SSO-01 | 使用当前有效身份向服务端申请短时、一次性跳转票据 | 票据绑定本人、目标及服务端规定的有效期，不在 URL 放入长期 JWT 或 upload_key |
| EXP-SSO-02 | 系统浏览器打开服务端允许的工作台目标，兑换票据建立浏览器会话 | 只允许受控目标，禁止任意外部重定向；同一票据不能重复兑换 |
| EXP-SSO-03 | 进入对应课程、任务或提交详情 | 目标权限由服务端再次校验；票据过期、无权限、网络失败有明确提示和重试入口 |
| EXP-SSO-04 | 退出、账号切换及服务器切换时维持身份隔离 | 浏览器已有其他账号会话时不得静默以错误身份提交，兑换及会话切换行为须共同确定 |

已有票据方案不表示接口已经实现。票据签发/兑换、有效期、目标白名单、登出联动、浏览器会话及审计策略必须经服务端和工作台共同确定。接口未交付时可明确提示普通登录入口，但不能据此验收“免登录成功”。

## 十三、服务端联合设计与实施门槛

以下为待设计的能力契约，不是已有 URL，也不承诺服务端已提供。

| 能力 | 需共同确定的输入、输出和规则 |
| --- | --- |
| 课程与任务读取 | 当前身份、课程/任务标识、班级权限、任务详情及资源、分页/状态/错误语义 |
| 项目关联 | 项目标识、关系基数、关联/变更/解除、权限验证、并发版本和历史 |
| 成果提交与读取 | 任务及项目、材料与版本、上传限制、幂等、状态流转、时间和反馈 |
| 工作台票据 | 有效身份、受控目标、短时票据、单次兑换、会话处理及失效错误 |
| 采集归属扩展 | 事件与课程/任务/项目的关联时机、无法归属的处理、历史数据迁移和审计 |

启动实施前共同评审并形成：领域模型与权限矩阵、实际端点与字段、错误及状态契约、数据迁移方案、插件和工作台 UI、测试账号与联调环境、版本依赖和验收记录模板。服务端从认证身份确定学生，不信任客户端传入的 student_id 作为授权依据。

交付顺序：先设计契约及服务端能力，再接课程任务面板与项目关联，随后接成果提交与票据，最后完成三门 Java 课程闭环及跨 IDE 验证。当前采集基础版按自身范围独立交付。
